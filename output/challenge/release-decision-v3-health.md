## 2) 릴리즈 게이트 — v3 적용

게이트 입력값: **P0 1건 / P1 10건 / P2 5건**.

| 게이트 | 규칙 | v3 대상 |
|---|---|---|
| 🔴 출시 보류 | 미해결 **P0 > 0** | **TC-010(수정 중 강제종료 시 누적 건강데이터 유실)** 실패 시 즉시 보류 |
| 🟡 조건부 출시 | P0=0 AND 미해결 P1 ≤ 2 | TC-010 통과 & 미해결 P1 2건 이하 시 승인 출시 |
| 🟢 출시 가능 | P0=0 AND P1=0 | 기록·리포트·공유 P0·P1 전량 해결 시 정상 출시 |

> **건강기록 도메인 특유 해석**: P1이 10건으로 많다 = "치명적 블로커는 1개뿐이나, 데이터 정확도·개인정보(공유링크)·경계 집계처럼 '틀리면 신뢰를 잃는' 케이스가 두껍다"는 뜻. 조건부 출시 상한(≤2)에 걸리기 쉬우므로, 이 도메인은 **P1 회귀(플랜2)를 충분히 확보한 스프린트 배치가 사실상 필수**다.

## 3) 테스트 실행 우선순위 플랜 — v3

- **플랜 1 — 데이터 무결성 P0 + 핵심 기록 경로**
  - 대상: TC-010(강제종료 정합성, P0) + TC-001·002(기록 정상 저장)·TC-012(공유 링크 생성)
  - 근거(리스크): TC-010은 누적 건강데이터의 **비가역 손실** — 건강기록은 사용자가 오래 쌓는 데이터라 손실 시 복구 불가·신뢰 붕괴. 1건 실패 시 🔴 보류 즉시 확정.
  - 실행 시점: QA Day 1 오전.
- **플랜 2 — 데이터 정확도·개인정보·경계 P1 회귀**
  - 대상: TC-004(형식 위반→그래프 오염)·TC-006(비정상 범위, 명세미정의)·TC-009(저장 중 끊김)·TC-013(만료 링크 개인정보 노출 방지)·TC-015(30일 집계 경계)
  - 근거(리스크): 서비스는 안 죽지만 **틀린 건강 수치·개인정보 노출**은 의료 맥락에서 신뢰를 직접 훼손(수의사 공유 기능 있음). 미해결 수가 조건부 출시 상한 초과 여부를 판정.
  - 실행 시점: P0 PASS 후 Day 1 오후.
