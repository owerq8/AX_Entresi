# 엔트레씨 — 기획서 기반 QA 체크리스트 자동 생성 파이프라인

> **AX 해커톤 [07] 산출물** · 글로벌 펫 플랫폼 **Petbbi(펫삐)** DA/PM/마케터
> 작성자 **김규리** · 2026-07-01 · Basic → Standard → Challenge **전 단계 완주**

기획서(`.md`) 하나를 넣으면 **구조분석 → 케이스설계 → 우선순위 점수화 → 엣지케이스 자동보완 → 릴리즈 게이트 판정**까지 한 번의 실행으로 나오는, **재현 가능한 QA 파이프라인**입니다.

체크리스트 1장을 손으로 만든 것이 아니라, **"어떤 기획서를 넣어도 동일 품질로 재현되는 시스템"** 을 설계하고 성격이 다른 기획서 4종(AI·결제·CRUD·예약)으로 실증했습니다.

---

## 풀려는 문제

Petbbi는 전담 QA팀 없이 PM/개발자가 QA를 겸임합니다. 기능이 늘 때마다 아래 문제가 반복됐습니다.

| #  | 페인포인트     | 증상                                                            |
| -- | -------------- | --------------------------------------------------------------- |
| ① | QA 누락        | 사진 없음·네트워크 끊김·권한 없음 같은 엣지케이스가 매번 빠짐 |
| ② | 우선순위 부재  | P0/P2 기준이 문서화 안 돼 출시 직전 "뭐부터 막지?" 혼선         |
| ③ | 반복 공수      | 빈 상태·로딩·에러 케이스를 매 스프린트 손으로 다시 작성       |
| ④ | AI 폴백 미명시 | 생성 결과가 기준 이하일 때 대체 흐름이 기획서에 없음            |

> 기획서는 **정상 동작(Happy Path)만** 기술돼 있고 예외·실패·폴백 흐름은 빠져 있습니다. **이 공백을 메우는 것이 핵심.**

---

## 파이프라인 (5단계)

```
STEP 1  구조분석      H2(섹션)/H3(항목)·수치기준·예외 미기술 문장 탐지
STEP 2  케이스설계    Happy/Unhappy/Edge 분류 + 규칙엔진으로 엣지 도출 + 우선순위 판단
STEP 3  생성          표준 9컬럼 CSV 저장
STEP 4  자가점검      섹션 커버리지·P0 포함·엣지 4유형 중 3유형+ 확인
STEP 5  릴리즈 판단   점수화 → 3-tier 게이트 → 실행 플랜 (Challenge)
```

이 5단계를 단일 스킬 **`/spec-to-qa <기획서경로>`** 하나로 묶어, 명령 1번에 전체 파이프라인이 돌아갑니다.

## 빠른 시작

### 요구사항

- [Claude Code](https://claude.com/claude-code) CLI (`claude` 명령)
- 웹 대시보드를 볼 경우: Python 3.9+, `pip install -r requirements.txt` (`streamlit`, `pandas`)

### QA 체크리스트 생성

Claude Code 대화 안에서:

```
/spec-to-qa data/product_spec_petbbi_v1.md
```

또는 headless 스크립트로 무인 실행:

```powershell
# Windows / PowerShell
./run-pipeline.ps1 data/product_spec_petbbi_v1.md   # 특정 기획서 1건
./run-pipeline.ps1                                   # data/*.md 전체 일괄
```

```bash
# macOS / Linux
./run-pipeline.sh data/product_spec_petbbi_v1.md
```

→ `output/qa-checklist-<기획서명>.csv` 생성 (+ 커버리지 리포트·릴리즈 게이트는 대화 로그로 출력)

### 웹 대시보드 실행

```bash
pip install -r requirements.txt
streamlit run streamlit_app.py     # http://localhost:8501
```

배포 방법은 [DEPLOY.md](DEPLOY.md) 참고 (Streamlit Cloud, API 키 불필요).

## 산출물 형식 — 표준 9컬럼 CSV

`기능섹션 · 테스트케이스ID · 테스트케이스제목 · 테스트유형 · 사전조건 · 테스트절차 · 기대결과 · 우선순위 · 출처`

- **테스트유형**: Happy Path / Unhappy Path / Edge
- **우선순위**: P0 / P1 / P2
- **출처**: `기획서기반` vs `AI추가` — 엣지케이스를 1급 컬럼으로 명시해 "스펙 결함인가 수용할 예외인가"를 트리아지

## 핵심 설계

### 1) 엣지케이스 규칙엔진

기획서의 동작 키워드를 표에 대입해 엣지 후보를 **기계적으로** 도출합니다(감이 아닌 규칙).

| 동작 키워드                | 자동 매칭 엣지케이스                                |
| -------------------------- | --------------------------------------------------- |
| 업로드/촬영/등록           | 권한 미허용, 네트워크 끊김, 용량/형식 초과          |
| 생성/연산(AI·결제 비동기) | 처리 실패·타임아웃, 결과 미달 폴백, 동시 요청 충돌 |
| 한도/횟수/기간             | 한도 직전/직후 경계값                               |
| 목록/조회                  | 빈 상태(0건) 안내                                   |
| 계정/삭제/해지/환불        | 데이터·상태 정합성, 비가역 시점 경계값             |
| 결제/수단 등록             | 결제 실패, 수단 만료·중복, 결제 중 이탈            |

+ Petbbi 도메인 특화 트리거 7종(AI 폴백 정합성, 다묘 한도, 다국어 폴백, 국가별 권한, 펫추모 자동생성 방지 등).

### 2) 우선순위 100점 점수식

| 배점 | 요소                                                                 |
| ---- | -------------------------------------------------------------------- |
| 50   | 서비스 중단 심각도 (크래시·무한로딩·비가역 손실·핵심 플로우 불가) |
| 30   | 영향 사용자 범위 (전체 vs 특정 세그먼트)                             |
| 20   | 가역성/우회 가능성 (비가역·규제 vs 즉시 복구)                       |

**판정**: ≥80 → P0 / 50–79 → P1 / <50 → P2 · 점수와 무관하게 P0로 올리는 **도메인 즉시 승격 6종**(이중청구·데이터 손실·규제·펫추모 등) 병행.

### 3) 릴리즈 게이트 (3-tier 기계 판정)

| 게이트         | 규칙               | 조치                                         |
| -------------- | ------------------ | -------------------------------------------- |
| 🔴 출시 보류   | 미해결 P0 > 0      | 1건이라도 있으면 출시 불가, 핫픽스 후 재검증 |
| 🟡 조건부 출시 | P0 = 0 AND P1 ≤ 2 | PM 승인 하 출시, 남은 P1은 릴리즈노트 명시   |
| 🟢 출시 가능   | P0 = 0 AND P1 = 0  | 정상 출시, P2는 백로그 이관                  |

### 4) 신뢰성 가드레일

스펙이 빈약하면 케이스를 **지어내지 않고** 정직한 미달 사유를 보고하고(C1), 명세 모순은 `기획확인필요`로 태깅(C2)합니다.  v4 기획서에서 도메인 승격이 0건 발동한 것이 "억지 P0를 만들지 않는다"는 증거입니다.

## 재현성 실증 (기획서 4종)

| 실행 | 입력            | 성격              | 건수 | 엣지(AI추가) | P0         |
| ---- | --------------- | ----------------- | ---- | ------------ | ---------- |
| v1   | petbbi_v1       | AI생성·소셜      | 53   | 27 (4유형)   | 12 (22.6%) |
| v2   | v2_subscription | 결제·구독        | 20   | 9 (3유형)    | 3 (15%)    |
| v3   | v3_health       | 순수 CRUD·리포트 | 16   | 8 (4유형)    | 1 (6.25%)  |
| v4   | v4_booking      | 예약·일정        | 26   | 11 (4유형)   | 1 (3.8%)   |

> 건수·P0 비율이 매번 다른 건 **기획서마다 리스크 구조가 다르기 때문**이지 규칙이 흔들려서가 아닙니다. "섹션당 Happy+Unhappy 전부 / 엣지 4유형 중 3유형+ / P0 자연 발생 시 포함"이라는 최소 품질 기준은 4건 모두 동일하게 재현됐습니다.

## 저장소 구조

```
.
├── .claude/skills/spec-to-qa.md   # 파이프라인 두뇌 (STEP 1~5 규칙)
├── run-pipeline.ps1 / .sh         # 새 기획서 무인 실행 래퍼
├── streamlit_app.py               # 웹 대시보드 (4탭)
├── data/                          # 입력 기획서 v1~v4 (.md)
├── output/
│   ├── basic/                     # v1 QA 체크리스트 (53건·9컬럼 CSV)
│   ├── standard/                  # 재현 CSV v2~v4 + 커버리지 리포트 + 양식 설계
│   ├── challenge/                 # 릴리즈 판단 v1~v4 + 점수식 전수검증
│   └── template.md                # 전 레벨 통합 제출 리포트
├── context/                       # 기업 컨텍스트 (회사·업계)
├── decisions.md                   # 의사결정 로그 (20+ 결정 기록)
├── DEPLOY.md                      # Streamlit 배포 가이드
└── hackathon_summary.md           # 작업 전체 요약
```
