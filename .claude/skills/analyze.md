# /analyze — 기획서 구조·누락 분석

data/product_spec_petbbi_v1.md 를 읽고 다음을 수행하라.

## 1. 구조 파악
- H2(기능 섹션)와 H3(세부 항목)를 목록으로 추출하고 개수를 센다 (기대: H2 6개)
- 각 섹션의 핵심 요구사항(입력값·동작·수치 기준)을 한 줄씩 요약

## 2. 수치 기준 추출 (경계값 후보)
- 명세에 등장하는 모든 수치/한도를 표로 정리: 이미지 해상도·이름 길이·재생성 횟수·본문 글자수·첨부 개수·인증 시간 등
- 최대치만 있고 최소치가 없거나, 그 반대인 모호한 기준을 표시

## 3. 누락된 예외 흐름 탐지
기획서는 "정상 동작"만 기술되어 있다. 다음 4유형으로 빠진 흐름을 섹션별로 진단한다.
- 빈 상태(Empty State): 데이터 0건일 때 안내
- 권한(Permission): 카메라/갤러리/알림 권한 미허용, 비로그인 접근
- 네트워크(Network): 생성 중 끊김, 업로드 중 끊김, 타임아웃
- 경계값(Boundary): 한도 초과, 최대/최소 입력
- AI 폴백: 생성 결과가 기준 이하일 때의 재시도·대체 흐름

## 출력
- 섹션 6개 × 요구사항 요약표
- 수치 기준 표 (경계값 테스트 후보)
- 섹션별 "빠진 엣지케이스 후보" 리스트 (다음 /insight 단계 입력)

> 임의 추정 금지. 명세에 없는 동작은 "명세 미정의"로 표시하고 추정하지 않는다.
