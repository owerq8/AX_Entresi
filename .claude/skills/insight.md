# /insight — 테스트 설계 기준 정의

/analyze 결과를 입력으로, 체크리스트 생성 전 판단 기준을 설계한다.

## 1. 테스트 유형 분류 기준
- **Happy Path**: 명세의 정상 흐름 — 섹션·세부항목당 최소 1개
- **Unhappy Path**: 잘못된 입력·실패 조건의 오류 처리 — 섹션당 최소 1개
- **Edge Case**: 빈 상태·권한·네트워크·경계값·AI 폴백 — 기획서에 없던 것

## 2. P0/P1/P2 우선순위 기준 (서비스 중단·사용자 영향도)
- **P0**: 서비스 중단·핵심 플로우 불가·데이터 손실 ("출시 불가능한가? YES")
  - 예: 캐릭터 생성 중 크래시, 계정 삭제 후 복구 불가, 회원가입 후 계정 미생성
- **P1**: 주요 기능 오작동·이탈 유발, 우회 가능하나 불편
  - 예: 재생성 한도 초과 안내 부재, 다국어 미반영, 알림 토글 미저장
- **P2**: 경미한 UX 영향
  - 예: 빈 상태 문구 누락, 비핵심 경계값

판단 시 다음 2축을 본다: **(1) 서비스 중단 여부 (2) 영향 사용자 범위**. 둘 다 높으면 P0.

## 3. 추가할 엣지케이스 확정
/analyze가 뽑은 후보 중 실제 추가할 케이스를 선별한다. 최소 다음 6종 권장:
- 카메라/갤러리 권한 미허용 시 업로드 (권한)
- 캐릭터 생성 중 네트워크 끊김 (네트워크)
- 재생성 1일 3회 한도 초과 (경계값)
- 10MB 초과 이미지 업로드 (경계값)
- 미지원 언어에서 일기 생성 (경계값/폴백)
- 계정 삭제 중 강제 종료 후 재진입 (네트워크/상태)
각 추가 케이스의 근거를 decisions.md에 기록할 것.

## 출력
- 테스트 유형 정의 + P0/P1/P2 기준 (근거 포함)
- 추가 엣지케이스 확정 리스트 (출처=AI추가)
