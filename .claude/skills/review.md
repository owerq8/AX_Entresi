# /review — 제출 전 자가 점검

output/qa-checklist-petbbi.csv 를 채점 기준에 비추어 점검하고 미흡 항목을 보완한다.

## Basic 체크리스트 (100점)
- [ ] 기능 섹션 6개가 모두 최소 1개 케이스로 커버되는가 (커버리지 40)
- [ ] 섹션마다 Happy Path + Unhappy Path 둘 다 있는가
- [ ] 기대결과가 구체적인가 (모호한 "정상 동작" 표현 없는가)
- [ ] 모든 행에 P0/P1/P2가 부여되고 분류 근거를 설명할 수 있는가 (우선순위 20)
- [ ] P0는 2축 판단 결과 자연 발생 시에만 부여됐는가 — 저위험 스펙이라 P0가 없으면 "P0 없음 + 최고 우선순위 근거"를 보고했는가(억지 P0 승격 금지, C1)
- [ ] 엣지케이스(AI추가)가 4유형 중 3유형·6건 이상인가 — 스펙 트리거가 부족하면 "가능한 유형·건수 + 부족 사유"를 보고했는가 (엣지 보완 30, C1)
- [ ] 컬럼 9개를 갖춘 .csv + 제출 링크 준비됐는가 (형식 10)

## Standard (+30)
- [ ] 새 기획서를 넣어도 동일 품질로 재생성되는가 (파이프라인 15)
- [ ] 양식·분류 기준을 본인이 설계하고 근거를 설명했는가 (양식 15)

## Challenge (+30)
- [ ] 릴리즈 게이트 기준·실행 우선순위 플랜이 실효성 있는가 (실효성 20)
- [ ] 우선순위 점수화·게이트 기준을 본인이 설계했는가 (양식·기준 10)

## 범위 점검 (제외 항목 혼입 금지)
- [ ] 성능·부하, 백엔드/API 내부 로직, 디자인 QA(폰트·컬러·픽셀), AI 모델 품질 주관 평가, 보안·침투 테스트, 일정 관리 케이스가 섞이지 않았는가

## 출력
- 항목별 ✅/⚠️/❌ 판정 + 예상 점수
- 보완이 필요한 케이스 목록과 수정안
